# Source Transparency Policy

## Purpose

ClawNews exists to make source context visible. Generated summaries are useful only when readers can inspect where the information came from and what is unknown.

## Core Rules

- Every event brief must link back to the source articles used to create it.
- Generated claims must be traceable to one or more source articles.
- Source ownership, funding, affiliation, and stakeholder context must be labeled when known.
- Unknown metadata must be shown as unknown, not guessed.
- Do not claim a source is biased without explaining the basis.
- Separate ownership, funding, editorial tendency, audience, and article-specific framing.
- Use confidence labels: high, medium, low, or unknown.
- Distinguish verified facts from inferred incentives.
- Do not state ownership or funding claims without a source or verification pathway.
- Disagreement between sources must be preserved when material to the event.
- Corrections and meaningful updates should appear in the brief change log.
- Never claim perfect neutrality. Present structured comparison, convergence, disagreement, and confidence.

## Source Metadata

Source cards should distinguish:

- Confirmed ownership or parent organization.
- Public funding, private funding, subscriptions, advertising, grants, or mixed models when known.
- Political, state, corporate, nonprofit, advocacy, or trade affiliations when known.
- Editorial notes that affect interpretation.
- Unknown or unverified fields.

Metadata should include provenance whenever possible. If the system cannot explain where a source note came from, the note should not be treated as confirmed.

## Generated Summaries

Generated text must not imply certainty beyond the available sources. Summaries should use careful language when:

- Reports conflict.
- Only one source has reported a claim.
- Source metadata is incomplete.
- Article text is unavailable and only RSS summaries were used.
- The event is developing.

## Ranking And Ordering

ClawNews may order briefs and sources for readability, freshness, or relevance. It should not hide material source disagreement because it is inconvenient or messy.

If source weighting is introduced later, the broad reason for weighting should be inspectable by users or documented in policy.

## Corrections

When source articles change, new articles contradict earlier claims, or generated briefs are updated, ClawNews should record:

- What changed.
- When it changed.
- Which source or pipeline step caused the change.
- Whether the previous brief contained an unsupported or outdated claim.

## User-Facing Promise

ClawNews should make it easy to tell the difference between:

- What sources reported.
- What the system inferred.
- What remains unknown.
- Why a source or stakeholder may have an incentive to frame the event in a particular way.
